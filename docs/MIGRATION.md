# 从老系统迁移数据

迁移在系统里是一个正式功能（侧边栏 **Data migration**），不是一次性脚本：可以预览、可以反复导入、每次导入都能整批回滚。

## 推荐顺序

1. **先建用户。** 在 Users 里把同事建好，并在"Other names"里填老表格里出现过的简称（Win、CL、Cathy…）。这样导入时 Partner / Preparer / Responsible Person 会自动匹配到真人。
2. **每块看板导一次。** 选择目标看板，上传该看板的导出文件（或直接连 ERPNext）。
3. **检查列映射。** 系统已经按老系统的列名和 ERPNext 字段名自动匹配；确认一遍，不需要的列选"Don't import"。
4. **匹配值。** 只列出没对上的值：状态、选项、人名。可以指向已有值、新建，或者留空。
5. **Check。** 看"Ready / With warnings / With errors"。有 error 的行不会导入。
6. **Import。** 在后台执行，完成后显示报告：
   - 每种结果的行数（created / updated / skipped / error）；
   - **对账**：每一列在源文件里有值的行数，和导入后系统里有值的行数。两者不一致会标出来。
7. 不满意就 **Roll back this import**，改映射后重来。

## 为什么优先用 ERPNext 直连，而不是 CSV

老系统的导出只包含当时页面上显示的列，而且常被 Excel 另存过：

| 问题 | 现象 | 系统的处理 |
| --- | --- | --- |
| 编码 | Excel 中文版另存为 GBK，直接按 UTF-8 读会乱码 | 依次尝试 UTF-8 / UTF-8-BOM / GB18030 / CP1252，结果显示在页面上 |
| 时间被截断 | "Last Updated" 变成 `55:30.0` | 默认不导入这一列 |
| 前导单引号 | `'-`、`'@Cathy Lau …` | 自动去掉；`-` 视为空 |
| HTML 实体 | `R&amp;D` | 还原成 `R&D` |
| 日期格式混杂 | `2027/5/15`、`20260911`、`Aug-26` | 按字段类型解析；无法识别的会在 Check 里列出 |
| 多值 | `Joe Liu; Jean Ren` | 按 `;`、`,`、换行、`/` 拆分 |
| 没有项目名列 | Accounting 导出只有客户名 | 用"Item name when the source has none"模板生成，默认 `{client} - {board}` |
| 同一客户多行 | `VELLA, Kristy` 出现两次 | 同一个客户，两条 item；重复导入时按出现顺序（#2）对应 |

ERPNext 直连读取完整字段、团队、软件、Updates 和月度状态，并且每行有稳定的 ERPNext 单据号，重复导入最可靠。需要在 ERPNext 里为一个只读用户生成 API Key / Secret；密钥只在那次请求里使用，不会保存。

## 重复导入

每行导入后，系统记住"来源 + 看板 + 行标识 → 新系统里的哪一条"（`external_refs`）。再导入同一批数据会**更新**已有的行，不会重复创建。CSV 的行标识默认是 `Client Name`（可以在上传时改成多列组合）。

## 正式切换建议

1. 在测试环境完整导一遍，团队试用几天。
2. 定一个切换时间点：老系统停止编辑 → 用 ERPNext 直连做最后一次导入 → 对账 → 新系统开始使用。
3. 老系统保留只读一段时间，作为核对依据。
