## 新增的（老系统没有）

- 数据迁移模块（CSV / ERPNext，映射、对账、回滚）
- 实时刷新：同事或自动化改了数据，打开的看板自动更新
- 客户级字段和镜像列
- 工作区配置界面：字段、状态、角色、看板（零代码扩展）
- 回收站、看板归档与恢复
- 每个写操作都有审计和事件，后续模块直接订阅
- 对外接口：个人 API token、Webhook、外部 ID 映射、字段默认值（[INTEGRATIONS.md](INTEGRATIONS.md)）

## 已知限制（演示版）

- 看板一次加载全部行（分页拉取后在浏览器里排序）。几千行以内很流畅；更大规模时切换到服务端分页（接口已支持）。
- 界面文字的中文翻译只覆盖了导航，其余仍是英文；框架已就绪，可逐步补 `zh-CN.json`。
- Engagement Letter 目前是链接字段；文件上传需要文件存储模块。
- 前端端到端测试（Playwright）尚未纳入 CI，目前靠手工和脚本验证。

## 后续计划（建议顺序）

1. **试用与修正**：团队用真实数据试用演示版，收集问题。
2. **报表**：按状态类别、负责人、截止日的汇总视图；利用已有的筛选语言。
3. **邮件模块**：Microsoft 365 / Gmail 连接；待处理邮件提示；邮件线程挂到客户和项目上（`external_refs`）。
4. **通知渠道**：邮件摘要、每日待办提醒（订阅现有 `notify.requested` 事件）。
5. **文件**：附件存储（澳洲区域）、Engagement Letter 上传、PDF/Word 文本提取。R&D 报告模块的前提，建议提前。
6. **AI 网关**：澳洲区域推理、客户同意校验、脱敏、留痕；先做邮件回复草稿（人工审核后发送）。R&D 报告模块的前提，建议提前。
7. **R&D 报告（RDTI）**：挂在 Grants 项目上，材料导入 → 证据评估 → Checklist → 带引用的报告初稿和核查模式。设计见 [RDTI.md](RDTI.md)、[ADR-0009](adr/0009-rdti-report-module.md)。
8. **CRM**：线索与商机作为一个新的工作区 + 模块，复用看板、自动化、客户。
9. **Shared drive 同步**：评估后作为独立模块接入。
